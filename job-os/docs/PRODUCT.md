# Job OS

## Product Vision

Job OS is a personal job-hunting operating system designed to help a candidate find, qualify, prepare, track, and learn from job opportunities.

The primary goal is not to maximize the number of applications.

The goal is to maximize interview opportunities per hour spent applying.

## Core Workflow

FIND → QUALIFY → APPLY → TRACK → LEARN

## Core Problems

The user currently spends significant time:

1. Finding job opportunities across different sources.
2. Reading job descriptions manually.
3. Determining whether a job is worth applying for.
4. Tailoring CVs and application materials.
5. Repeating this process for every application.
6. Tracking applications and outcomes.
7. Learning from which applications generate responses.

Job OS should reduce this repetitive work and improve the quality and efficiency of the job search.

## Core Product Areas

1. Job Discovery
2. Job Intelligence
3. Candidate Profile
4. Application Preparation
5. Application Pipeline
6. Job Search Analytics
7. Skills and Gap Analysis

## Initial MVP

The first MVP should focus on:

1. Job input
2. Job parsing
3. Requirement extraction
4. Candidate-job matching
5. Gap analysis
6. Application preparation
7. Application tracking

## Initial Job Input Methods

The system should eventually support:

- Pasted job descriptions
- Job URLs
- Screenshots
- PDFs
- Manually entered jobs

## Important Product Principle

The system should reduce decision fatigue.

The user should not need to manage dozens of disconnected tools.

A job should move naturally through the system:

DISCOVERED
→ QUALIFIED
→ PREPARING
→ READY
→ APPLIED
→ FOLLOW-UP
→ INTERVIEW
→ OUTCOME

## Candidate Profile

The candidate profile is the source of truth.

CVs and application documents should be generated from the structured candidate profile rather than treating one CV as the permanent source of truth.

The profile should contain:

- Education
- Experience
- Skills
- Projects
- Certifications
- Demonstrable capabilities
- Portfolio evidence
- Learning history

## Matching Philosophy

The system should distinguish between:

- Strong evidence
- Transferable skills
- Evidence gaps

The system should not fabricate employment history but it should be creative and accomodating, credentials, or experience.

When a requirement is missing, the system should identify the gap and potentially recommend a project or learning activity that can create legitimate evidence.

## Application Philosophy

The system should prepare applications automatically where possible, but the user should remain in control of final submission.

Initial application workflow:

Analyze → Prepare → Review → Submit

## Analytics

The system should eventually measure:

- Applications
- Interviews
- Response rate
- Interview rate
- Application source performance
- Role performance
- CV version performance
- Time spent per application

The key optimization metric is:

Interview opportunities per hour spent applying.
